# Custom Resource Instance Naming Guide

## Overview

The infrastructure management system now supports custom resource naming, allowing you to create multiple instances of the same resource type with descriptive names.

## Syntax

```bash
./manage.pl add resource "<name>:<type>" -e <env> -r <region> [options]
```

- `<name>`: Custom instance name (e.g., db1, cache1, web-sg)
- `<type>`: Resource type or alias (e.g., rds-mysql, postgres, redis, sg)

## Your Client Scenario Examples

### Multiple Database Instances

```bash
# Create multiple MySQL databases
./manage.pl add resource "db1:rds-mysql" -e testing -p api-server -r us-west-2
./manage.pl add resource "db2:rds-mysql" -e testing -p api-server -r us-west-2
./manage.pl add resource "reporting-db:mysql" -e testing -p api-server -r us-west-2

# Create PostgreSQL databases  
./manage.pl add resource "analytics-db:postgres" -e testing -p api-server -r us-west-2
./manage.pl add resource "warehouse-db:postgresql" -e testing -p api-server -r us-west-2
```

**Results in directory structure:**
```
envs/testing/api-server/us-west-2/
├── db1/                    # MySQL instance 1
│   ├── terragrunt.hcl
│   ├── inputs.json
│   └── deploy.pl
├── db2/                    # MySQL instance 2
│   ├── terragrunt.hcl
│   ├── inputs.json
│   └── deploy.pl
├── reporting-db/           # MySQL for reporting
├── analytics-db/           # PostgreSQL for analytics
└── warehouse-db/           # PostgreSQL data warehouse
```

### Multiple Cache Instances

```bash
# Redis instances for different purposes
./manage.pl add resource "session-cache:redis" -e prod -r us-east-1
./manage.pl add resource "api-cache:redis" -e prod -r us-east-1
./manage.pl add resource "user-cache:elasticache" -e prod -r us-east-1
```

### Multiple Security Groups

```bash
# Different security groups for different services
./manage.pl add resource "web-sg:security-group" -e prod -r us-west-2
./manage.pl add resource "app-sg:sg" -e prod -r us-west-2
./manage.pl add resource "db-sg:sg" -e prod -r us-west-2
./manage.pl add resource "admin-sg:security-group" -e prod -r us-west-2
```

## Advanced Examples

### Microservices Architecture

```bash

./manage.pl add resource "user-service-db:postgres" -e prod -r us-west-2
./manage.pl add resource "user-service-cache:redis" -e prod -r us-west-2

./manage.pl add resource "order-service-db:mysql" -e prod -r us-west-2  
./manage.pl add resource "order-service-cache:redis" -e prod -r us-west-2

./manage.pl add resource "payment-service-db:postgres" -e prod -r us-west-2
./manage.pl add resource "payment-service-cache:redis" -e prod -r us-west-2
```

### Environment-Specific Naming

```bash
# Development environment
./manage.pl add resource "dev-primary-db:mysql" -e dev -r us-west-2
./manage.pl add resource "dev-test-db:postgres" -e dev -r us-west-2

# Staging environment  
./manage.pl add resource "staging-db:mysql" -e staging -r us-west-2
./manage.pl add resource "staging-cache:redis" -e staging -r us-west-2

# Production environment
./manage.pl add resource "prod-master-db:mysql" -e prod -r us-east-1
./manage.pl add resource "prod-read-replica:mysql" -e prod -r us-west-2
./manage.pl add resource "prod-cache-cluster:redis" -e prod -r us-east-1
```

## Backward Compatibility

The traditional method still works:

```bash
# These still work as before
./manage.pl add resource "vpc" -e testing -r us-west-2
./manage.pl add resource "eks" -e testing -r us-west-2 -z us-east-1
./manage.pl add resource "rds-mysql" -e testing -r us-west-2
```

## Resource Type Aliases

All existing aliases work with custom naming:

| Alias | Full Type | Example Usage |
|-------|-----------|---------------|
| `mysql` | `rds-mysql` | `db1:mysql` |
| `postgres` | `rds-postgres` | `warehouse:postgres` |
| `postgresql` | `rds-postgres` | `analytics:postgresql` |
| `redis` | `elasticache` | `session:redis` |
| `sg` | `security-group` | `web:sg` |
| `apigw` | `api-gateway` | `public:apigw` |

## Generated Files

Each custom-named resource generates:

1. **Directory**: `envs/<env>/<project>/<region>/<custom-name>/`
2. **terragrunt.hcl**: Configured for the specified resource type
3. **inputs.json**: Generated by terraform-module-analyzer
4. **deploy.pl**: Integration with terragrunt-deploy.pl
5. **output.json**: Created after successful deployment

## Best Practices

### Naming Conventions

- **Descriptive names**: `user-db`, `session-cache`, `web-sg`
- **Purpose-based**: `primary-db`, `read-replica`, `backup-db`
- **Service-based**: `auth-service-db`, `payment-cache`
- **Environment prefix**: `dev-db1`, `staging-cache`, `prod-master`

### Organization Patterns

1. **By Service**: Group related resources by service/application
2. **By Function**: Group by database role (primary, replica, backup)
3. **By Environment**: Prefix with environment for clarity
4. **By Performance Tier**: `high-perf-db`, `standard-cache`

## Error Handling

### Invalid Resource Type
```bash
$ ./manage.pl add resource "db1:invalid-type" -e dev -r us-west-2
Error: Unknown resource type 'invalid-type'
```

### Type Suggestions
```bash  
$ ./manage.pl add resource "db1:mysql-rds" -e dev -r us-west-2
Error: Unknown resource type 'mysql-rds'
Did you mean one of these?
  - rds-mysql
  - mysql
```

## Integration with Existing Tools

### With terraform-module-analyzer
```bash
# After creating resources, analyze modules to generate inputs.json
./admin/terraform-module-analyzer.pl
```

### With terragrunt-deploy
```bash  
# Deploy specific custom-named resources
./terragrunt-deploy.pl -d envs/testing/api-server/us-west-2/db1
./terragrunt-deploy.pl -d envs/testing/api-server/us-west-2/db2

# Deploy all resources in a region
./terragrunt-deploy.pl -d envs/testing/api-server/us-west-2
```

### With resource templates
```bash
# Generate templates for new resource types
./admin/create-resource-template.pl -t rds-oracle
./manage.pl add resource "legacy-db:rds-oracle" -e prod -r us-east-1
```
